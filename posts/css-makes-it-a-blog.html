给页面加 CSS 那天，我学会了一件事：CSS 出错不会告诉你

2026 年 11 月 27 日

第一版页面最扎眼的是一张图——它撑满整个屏幕，把页头压成了一条缝。

第二扎眼的是字：标题大得像横幅，正文贴着屏幕边缘，链接是九十年代网页那种蓝紫色。

加上 CSS 三分钟之后，它就勉强能看了。但过程不太顺。

CSS 要放对地方

三种写法，我直接用第三种：

<!-- 行内 -->
<h1 style="color: red">标题</h1>

<!-- 内部 -->
<style> h1 { color: red; } </style>

<!-- 外部（推荐） -->
<link rel="stylesheet" href="style.css">

理由很简单：一处改，全站变。等你有五十篇文章，不可能每篇都去改一次颜色。

有个细节绊了我一下：index.html 里写 href="style.css" 就行，但 posts/hello.html 里必须写 href="../style.css"——它在子目录里，得先退一层才找得到。

相对路径是相对于“当前这个文件在哪”，不是相对于项目根目录。

盒模型：一个元素就是四个数字

页面上每个元素都是一个矩形盒子：

+-------------------------------+
|  margin                       |
|  +-------------------------+  |
|  |  border                 |  |
|  |  +-------------------+  |  |
|  |  |  padding          |  |  |
|  |  |  +-------------+  |  |  |
|  |  |  |  content    |  |  |  |
|  |  |  +-------------+  |  |  |
|  |  +-------------------+  |  |
|  +-------------------------+  |
+-------------------------------+
  • margin：最外层，永远是透明的，作用是"把别的元素推开"
  • border：看得见的边框线
  • padding：内边距，背景色会铺满它
  • content：内容本身

对我来说它就是 struct box { int content, padding, border, margin; }。

关键是把 padding 和 margin 分清：

  • padding：盒子内部的空隙，背景色会把它填满
  • margin：盒子外部的空地，永远是透明的

还有个反直觉的默认行为：width 只算 content。写 width: 300px; padding: 20px，实际占 340px——盒子被撑大了。

所以每个项目的第一条 CSS 都是这句：

*, *::before, *::after {
  box-sizing: border-box;
}

意思是“width 从今往后包含 padding 和 border”。* 是通配符，选中所有元素。

一个字母，整条规则消失

我拼错过这一行：

*, *::bedore, *::after {   /* before 打成了 bedore */
  box-sizing: border-box;
}

页面看起来完全正常。

直到我在 F12 的样式面板里翻了一遍，才发现：box-sizing 一条都没生效。

原因是 CSS 的一条规矩：逗号分隔的选择器列表里，只要有一个无效，整条规则全部作废——不是跳过那一个，是整条丢掉。

它当时没造成后果，纯属侥幸（我还没给任何元素写死宽度）。但这件事让我记住了一句话：

CSS 出错不会报错，它只是静默地不生效。

这是从 C 转过来最不适应的一点。编译器会指着行号骂你，CSS 只会假装什么都没发生。

排查方法，从那天起我一直在用：

  1. 按 F12，选中那个元素
  2. 右侧“样式”面板看规则在不在
  3. 被划掉的 = 被更高优先级的规则覆盖了
  4. 压根看不到的 = 语法错误，整条被丢弃

让三个链接排成一行：Flexbox

导航的三个链接本来挤在一起，间距由源码里的换行产生，完全没法精确控制。

nav {
  display: flex;
  gap: 20px;
}

两行解决。Flexbox 的模型是：给容器加上 display: flex，它的直接子元素就变成沿主轴排列的格子。

两个轴记住就够了：主轴是排列方向（默认水平），交叉轴是垂直方向。justify-content 管主轴，align-items 管交叉轴。

gap 和 margin 的区别值得单独说，因为它俩经常被混：

属性 属于谁 效果
margin 元素自己 它和所有邻居之间的距离，最外侧也会留空
gap 容器 只在子元素之间留空，最外侧不额外加

用 margin-right: 20px 给三个链接加间距，最后一个右边也会空出 20px——因为它不知道自己是不是最后一个。gap 没有这个问题。

而且 gap 只在 flex / grid 容器里有效，普通容器上写了等于没写。

响应式：同一个页面，两个尺寸

@media (max-width: 600px) {
  body    { font-size: 15px; }
  h1      { font-size: 1.6rem; }
  article { padding: 16px 18px; }
}

读作“视口宽度不超过 600px 时，这些规则才生效”。

这条能成立的前提，是阶段一那个毫不起眼的 <meta name="viewport" content="width=device-width, initial-scale=1.0">。没有它，手机浏览器会假装自己有 980px 宽，媒体查询永远不触发。

验收响应式别用手拖窗口。按 F12 再按 Ctrl+Shift+M 开设备模拟——这是职业前端每天在用的东西。

结果

灰白背景，居中一栏，三张白色圆角卡片，鼠标悬停时有淡淡的阴影。

离“设计感”还差得远，但它终于像一个站点了。

回头看，CSS 真正的门槛不是属性多，而是那个反馈回路：你写错了，它不说话；你必须自己知道去哪儿看。学会看 F12 的样式面板，比背下二十个属性有用得多。
