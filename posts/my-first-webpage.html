我的第一个网页，和那个让我愣住的 F12 面板

2026 年 11 月 26 日

写第一个网页那天，我在 index.html 里敲了九行：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的博客</title>
</head>
<body>
  <h1>你好，世界</h1>
  <p>这是我的第一个网页。</p>
</body>
</html>

双击打开，一行巨大的黑字，没有边距，没有留白，白底黑字占满整个屏幕。

丑归丑，但它真的跑起来了。然后我按了 F12。

骨架里每一行都在干一件具体的事

我一开始以为 <!DOCTYPE html> 和 lang="zh-CN" 是形式主义，其实每一行都有用处：

那一行 干什么
<!DOCTYPE html> 让浏览器用标准模式解析。不写会走模仿老 IE 的“怪异模式”，布局会莫名其妙错位
lang="zh-CN" 声明这是中文。读屏软件用中文发音，浏览器会问你“要不要翻译”
<meta charset="UTF-8"> 编码。不写或者写错，中文全变乱码
<meta name="viewport"> 手机端的宽度策略。做响应式时它是前提
<title> 标签页上的文字，也是搜索结果的第一行

charset 那行我后来真栽过：文件存成了别的编码，浏览器照着 UTF-8 解码，整页变成 æˆ‘çš„åšå®¢ 这种鬼画符。乱码永远是“文件编码”和“声明编码”对不上，不是玄学。

head 和 body 的分工也随之清楚了：head 装的是“关于这个页面的信息”，不显示；body 才是用户看得见的东西。

元素、属性，其实就是一个 struct

<a href="posts/hello.html">阅读全文</a>

拆开看：<a 是开始标签，</a> 是结束标签，中间是内容，三者合起来叫一个元素。href="..." 是属性，键值对，只能写在开始标签里。

用 C 的话说：一个元素 ≈ 一个 struct，属性 ≈ 它的字段。只不过它的字段全是字符串，而且大部分可以省略。

这个类比一路通用。<img src="..." alt="..."> 就是 struct img { char *src; char *alt; }，只是它没有内容和结束标签。

为什么别写一堆 div

我最初那一版，所有东西都是 <div>：<div> 套 <div>，一层又一层，回头自己都看不出哪块是什么。

后来改成这样：

<header>  <!-- 页头：站名、介绍 -->
<nav>     <!-- 导航：一组链接 -->
<main>    <!-- 主体：一页只有一个 -->
<article> <!-- 一篇文章 -->
<footer>  <!-- 页脚：版权 -->

<article> 装一篇文章，<header> 装页头，光看标签名就知道这块是什么。

有个反直觉的点：这些标签默认长得和 <div> 一模一样，不会自动变好看。它们的价值在别处——

搜索引擎靠它理解你的页面结构，读屏软件靠它一键跳到正文。
视觉是 CSS 的事，结构是 HTML 的事，别指望 HTML 让页面变美。

愣住的那一刻：页面变了，文件没变

我在 F12 的“元素”面板里，双击 <h1> 里的文字，改成“我改过了”，回车——页面上立刻变了。

然后我按了 F5。

变回去了。

回 VS Code 打开 index.html，文件一个字都没变。

那一下我才明白，浏览器里那棵树和硬盘上那个文件，是两个东西。它们有正式的名字：

  • 硬盘上的文件：HTML 源码
  • 内存里的那棵树：DOM（Document Object Model）

用我熟悉的东西对一遍：

文件 DOM
磁盘上的文本 内存里的对象树
相当于 .c 源文件 相当于加载到内存里的 AST
编辑它 相当于在调试器里改变量

在调试器里把 int x = 5 改成 100，程序跑的时候是 100，但 .c 文件里还是 5，重新编译又回到 5。DOM 和文件的关系一模一样。

三条实际区别：

  1. 形态不同：文件是文本；DOM 里每个节点都是对象，有属性，能被程序读写
  2. 内容可能不同：浏览器会补全、会规范化——标签写成大写会统一成小写，嵌套写错了会被自动纠正
  3. 生命周期不同：文件持久存在，DOM 只在页面打开期间存在，刷新就重建

一句话：文件是“源码”，DOM 是“加载后的内存结构”。F12 是调试器，不是编辑器。

两个当天踩的坑

① 转义

我在代码块里写 #include <stdio.h>，页面上什么都没有。因为 <stdio.h> 被浏览器当成了一个标签，直接吞掉了。

HTML 里有三个字符必须写成实体：< → &lt;、> → &gt;、& → &amp;。

② pre 会保留所有空格

<pre> 保留换行和空格。好处是代码块能保持格式，坏处是你为了“HTML 好看”加的缩进，会原样出现在页面上。所以 <pre> 里的内容要顶格写，只在代码内部用缩进。

结尾

第一版页面丑得很彻底：巨大的黑字、蓝紫色的链接、一张撑满屏幕的图。

但它是有结构的。而且从那一刻起我明白了一件事：我写的从来不是“屏幕上那个东西”，我写的是一份会被浏览器解释的文本。

后面所有的调试，都发生在这两者之间。
